End-to-End SEO Website Production Process — Using Claude Code

The canonical 27-phase production guide for SEO-led client websites built with Claude Code in VS Code.

Mid-fi · internal

Status: canonical · adopted 3 August 2026 · owner: Raoul Müller Applies to: every SEO-led client website and page-set Digital Movement builds with Claude Code. Companion: lean-end-to-end-seo-website-process.md — the same process expressed as a seven-week Semrush-anchored schedule with durations, timeline variables and per-phase exit conditions. Use this document for what to do and in what order; use the lean version for how long it takes and when each thing happens. Related: README.md — the client-facing 8-phase map, the three-gate commercial rule and the eleven deliverable templates.

Operating model

Three actors are involved:

Role Responsibility
SEO strategist and website consultantOwns the business outcome, SEO strategy, information architecture, UX, visual direction, implementation decisions, technical SEO, QA, launch, and optimisation
CopywriterOwns message architecture, final page copy, metadata wording, CTAs, FAQs, and copy approval
Claude Code in VS CodeAnalyses the repository, generates implementation plans, builds and refactors the codebase, integrates approved content, runs validation, and documents the system

The SEO strategist and website consultant remains accountable for all final decisions. Claude Code executes defined work but does not independently decide positioning, SEO strategy, or final wording.

Phase 1 — Business and SEO discovery

Objective: Understand the client's business, commercial priorities, target audiences, search opportunity, and conversion requirements.

Owner: SEO strategist and website consultant.

Human activities

  • Interview the client
  • Identify priority services
  • Define target audiences
  • Define qualified leads
  • Understand the sales process
  • Review existing positioning
  • Gather analytics and Search Console data
  • Conduct keyword research
  • Review organic competitors
  • Identify existing technical issues
  • Define conversion objectives

Inputs

client-input/
├── interview-notes.md
├── existing-materials/
├── analytics-export.csv
├── search-console-export.csv
├── semrush-export.csv
└── competitor-list.md

Claude Code role

Claude helps organise raw inputs, identify missing information, and create structured discovery documents.

Prompt example

Read all files in:

- client-input/
- seo/raw-research/

Do not create website code.

Create the following documents:

- docs/website-brief.md
- docs/business-objectives.md
- docs/audience.md
- docs/positioning.md
- docs/conversion-strategy.md
- docs/requirements.md

Requirements:

1. Separate confirmed facts from assumptions.
2. Identify contradictions between source documents.
3. List missing information that materially affects the website.
4. Distinguish business objectives from SEO objectives.
5. Define the primary and secondary conversions.
6. Do not invent positioning, evidence, statistics, or client claims.
7. Preserve source references in each document.

At the end, provide:
- confirmed findings
- unresolved questions
- strategic risks
- recommended decisions requiring human approval

Phase 2 — Search-intent analysis and keyword clustering

Objective: Turn keyword research into defensible page opportunities.

Owner: SEO strategist and website consultant.

Claude Code role

Claude analyses research exports, groups keywords, identifies intent overlap, and proposes page clusters. It does not make the final decision about whether a page should exist.

Prompt example

Analyse:

- seo/keyword-research.csv
- seo/competitor-analysis.md
- docs/business-objectives.md
- docs/positioning.md

Create:

- seo/search-intent-map.md
- seo/topic-clusters.md
- seo/keyword-clusters.csv

For each keyword or keyword group, identify:

- primary search intent
- secondary intent where relevant
- commercial relevance
- target audience
- likely page type
- whether the topic deserves a dedicated page
- likely overlap with other clusters
- risk of cannibalisation
- priority: high, medium, or low

Rules:

- Do not create a separate page for every keyword.
- Group keywords that clearly satisfy the same intent.
- Distinguish informational intent from commercial service intent.
- Flag uncertain classifications.
- Do not treat search volume as the sole prioritisation factor.
- Consider business value, competition, and conversion relevance.

Provide a final section titled:
"Decisions requiring SEO strategist approval."

Human review

  • Are keywords grouped by actual intent?
  • Does each potential page have commercial or strategic relevance?
  • Are synonymous terms unnecessarily separated?
  • Are local pages genuinely justified?
  • Are there missing topics competitors cover well?

Phase 3 — Search-led sitemap and URL architecture

Objective: Determine which pages should exist and how they connect.

Owner: SEO strategist and website consultant.

Claude Code role

Claude proposes sitemap options, URL structures, navigation, internal links, and redirect implications.

Prompt example

Read:

- docs/business-objectives.md
- docs/audience.md
- docs/conversion-strategy.md
- seo/search-intent-map.md
- seo/topic-clusters.md
- seo/keyword-clusters.csv
- seo/current-performance.md

Do not write website code.

Propose a lean website architecture.

Create:

- docs/architecture/sitemap.md
- docs/architecture/page-inventory.md
- docs/architecture/navigation.md
- docs/architecture/user-journeys.md
- seo/architecture/keyword-to-page-map.csv
- seo/architecture/url-structure.md
- seo/architecture/internal-linking-plan.md
- seo/architecture/redirect-plan.csv

For each proposed page, document:

- page name
- proposed URL
- page type
- target search intent
- primary topic
- supporting topics
- business objective
- primary audience
- primary conversion
- parent page
- required internal links
- whether the page is new, retained, merged, or removed

Rules:

- Avoid multiple pages targeting the same intent.
- Do not create thin location pages.
- Preserve valuable existing URLs where practical.
- Flag every URL change that requires a redirect.
- Keep navigation understandable to users, not only search engines.
- Prefer fewer strong templates over many highly specialised templates.

Present two architecture options:
1. Lean minimum viable architecture
2. Expanded long-term SEO architecture

Recommend one, with explicit trade-offs.

Approval gate

Approve: sitemap · URLs · page inventory · navigation · keyword-to-page mapping · redirect strategy.

Objective: Create repeatable rules Claude follows across the project.

Prompt example

It must include:

2. Role ownership
3. Required documents to read
4. Content ownership rules
5. SEO page-creation rules
6. Design-system rules
7. CSS architecture rules
8. Component and template rules
9. Accessibility requirements
10. Technical SEO requirements
11. Validation commands
12. Definition of done
13. Prohibited actions

Important role rules:

- The SEO strategist and website consultant owns strategy, UX, design direction,
  technical SEO, and final implementation decisions.
- The copywriter owns final page copy and metadata wording.
- Claude must not silently rewrite approved copy.
- Claude must not create new indexable pages without an approved page strategy.
- Claude must not invent testimonials, statistics, reviews, clients, locations,
  or business claims.
- Claude must report uncertainty instead of filling gaps with fabricated facts.

Use concise, operational language.
Do not fill CLAUDE.md with generic software-development advice.

Objective: Create the styling architecture used across all pages.

Production: Claude Code.

Responsibilities:

reset.css
- browser normalisation
- box sizing
- media defaults
- reduced-motion handling
- accessible focus foundations

typography.css
- body text
- headings
- links
- lists
- prose
- labels and helper text

layout.css
- containers
- sections
- grids
- stacks
- split layouts
- responsive behaviour

utilities.css
- only essential single-purpose utilities
- accessibility helpers
- visibility helpers

components.css
- shared low-level components only

sections.css
- shared section compositions only

forms.css
- fields, states, validation, groups

navigation.css
- header, desktop navigation, mobile navigation

global.css
- import order
- document-level styles
- site-wide exceptions only

Rules:

- Do not put page-specific styles in global.css.
- Do not duplicate token values.
- Avoid excessive utility classes.
- Do not use !important except for documented accessibility utilities.
- Keep selectors low-specificity.
- Use mobile-first media queries.
- Preserve existing working styles unless explicitly replaced.

Run lint, tests, and build after implementation.

Core working rule

At every Claude Code stage, the prompt should define five things explicitly:

  1. Inputs — which files Claude must read
  2. Output — which files or deliverables it must create
  3. Constraints — what it must not change or invent
  4. Validation — which checks must be run
  5. Decision boundary — what requires human approval

This prevents Claude from turning an implementation task into an uncontrolled strategy, design, copywriting, and development exercise.
