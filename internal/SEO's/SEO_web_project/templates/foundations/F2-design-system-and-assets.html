The rule of two. A component is promoted into the design system on its second use — not its third, and never before it has been used once. Build the token skeleton before page one. Extract components out of page one. Never pre-build a component library; it will be rewritten after the first real page anyway. One stylesheet. Anything appearing on two or more pages is defined once, centrally. Duplicated per-page CSS is the single confirmed cause of cross-page quality drift.

1. Token skeleton

Written before page one. This is the only part of the system that is allowed to exist ahead of real pages.

:root {
  /* colour */
  --color-bg:        ;
  --color-surface:   ;
  --color-ink:       ;
  --color-ink-soft:  ;
  --color-rule:      ;
  --color-primary:   ;
  --color-accent:    ;
  --color-accent-ink:;

  /* type */
  --font-display: ;
  --font-body:    ;
  --step-0: ; --step-1: ; --step-2: ;
  --step-3: ; --step-4: ; --step-5: ;

  /* space */
  --space-1: ; --space-2: ; --space-3: ; --space-4: ;
  --space-5: ; --space-6: ; --space-7: ; --space-8: ;

  /* other */
  --radius:  ;
  --shadow:  ;
  --measure: 65ch;
  --wrap:    ;
}

Token hygiene

  • Declared in exactly one place — no second :root block anywhere
  • No page hardcodes a brand hex inline
  • Token names describe the role, not the value (--color-accent, not --gold)
