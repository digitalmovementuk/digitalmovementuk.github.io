The basePath trap. A project Pages site is served from /<repo>/. Root-relative asset paths (/assets/…) 404 there. Either set the base path correctly or use relative paths — and check the rendered page, not the source.

2. Coding standards

HTML

  • One <h1> per page, heading order unbroken
  • Landmarks: header, nav, main, footer
  • lang attribute set correctly
  • Semantic elements over div wherever one exists
  • Buttons are <button>, links are <a> — never the reverse
  • Form inputs have bound <label> elements
  • No inline styles

CSS

  • All shared styles in the shared stylesheet
  • Tokens declared exactly once
  • No brand hexes hardcoded in a page
  • Class naming convention followed: …
  • !important only with a recorded reason
  • Mobile block last in the file
  • Wide content scrolls in its own overflow-x: auto container

JavaScript

  • Page works with JS disabled for anything essential
  • No blocking scripts in <head>
  • No console errors or warnings
  • Third-party scripts load after consent
  • Event listeners cleaned up

Required practices

  • Images: modern format, correct dimensions, width/height set, lazy below the fold
  • Hero image preloaded and never lazy-loaded
  • Fonts self-hosted, subset, font-display: swap
  • Critical CSS inline where it measurably helps
  • No render-blocking resources

4. SEO standards

  • Unique title tag ≤ 60 characters
  • Unique meta description ≤ 155 characters
  • One H1, matching the copy document
  • Clean, readable, lowercase, hyphenated URLs
  • Canonical tag on every page
  • Open Graph and Twitter card tags
  • Structured data valid, matching visible content
  • robots.txt present and correct
  • XML sitemap present, returning 200, submitted
  • No noindex surviving from staging
  • Internal links use descriptive anchor text
  • Changed URLs 301-redirected
  • SEO and service pages pass the 242-item seo-page-qa-gate with zero blockers

5. Accessibility standard

Target: WCAG 2.2 AA.

  • Text contrast ≥ 4.5:1, large text ≥ 3:1 — measured on the rendered page
  • Non-text and UI contrast ≥ 3:1
  • Visible focus on every interactive element
  • Focus order matches visual order
  • Fully keyboard operable, no traps
  • Skip-to-content link
  • Alt text on every image; decorative ones alt=""
  • Errors announced and identified by more than colour
  • Tap targets ≥ 44×44px
  • Usable at 200% zoom
  • prefers-reduced-motion respected
  • Automated scan clean, plus a manual keyboard and screen-reader pass

6. Forms and data

  • Forms post to the real endpoint — never mailto:, which delivers nothing
  • Sending domain is on the endpoint's origin allowlist
  • Domains with umlauts must be allowlisted in their punycode form
  • Consent field sent with every submission
  • Consent checkbox unticked by default, purpose named, privacy policy linked
  • Server-side validation, not only client-side
  • Spam protection that does not break accessibility
  • Success and failure states both handled, with a usable fallback
  • A real test submission verified as arriving before launch

7. Security and privacy

  • HTTPS enforced, HTTP redirected
  • No secrets, keys or credentials in the repository
  • Dependencies current, no known critical vulnerabilities
  • No tracking before consent
  • Personal data minimised — collect only what is used
  • Privacy policy names every third party that receives data
  • External links: rel="noopener"

9. Definition of Done for any build

  • Matches the approved design; deviations documented
  • Zero placeholder content
  • All checklists above passed or explicitly overridden
  • No console errors
  • Verified in a rendered browser, not by reading the source
  • Handover document (06) complete
  • Handed to QA, not self-approved
